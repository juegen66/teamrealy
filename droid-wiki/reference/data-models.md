# Data models

This is the field-by-field reference for every table in `apps/api/src/database/schema.ts`, with relations from `apps/api/src/database/relations.ts`. The primitives pages cover the conceptual and relational view — [Workspace and project hierarchy](../primitives/workspace-and-project.md) and [Task model](../primitives/task-model.md) — and [apps/api/database](../apps/api/database.md) covers migrations and connection setup. This page is the exhaustive companion those pages link out to.

## Conventions used across every table

- **IDs** are `text` primary keys generated by `createId()` from `@paralleldrive/cuid2` via `$defaultFn`, unless the table says otherwise. Auth-facing tables that Better Auth writes (`session`, `team`, `team_member`, `billing_event`, `job_lease`) use plain text IDs.
- **Timestamps** written `timestamp(..., { mode: "date" })` map to JavaScript `Date` objects in Drizzle and to `timestamptz`/`timestamp` in Postgres. `created_at` is usually `defaultNow()`. `updated_at` is usually `defaultNow()` plus `$onUpdate(() => new Date())`, so Drizzle updates it automatically on writes.
- **Foreign keys** list their `onDelete` behavior, because cascades are decided in the schema, not in application code. The default reference (no behavior clause) is `no action`/`restrict`.
- **Uniqueness** is enforced by `unique(...)` (table constraint) or `uniqueIndex(...)` (index); ordering indexes are plain `index(...)`.
- The file also exports Better Auth-compatible aliases (`user`, `session`, `account`, `verification`, `workspace`, `workspace_member`, `invitation`, `organizationRole`, `team`, `teamMember`, `apikey`, `deviceCode`) so the auth adapter can map its models onto these tables.

## Identity and auth (Better Auth tables)

These tables are owned by Better Auth and consumed through its Drizzle adapter in `apps/api/src/auth.ts`. Kaneo adds a few columns on top of the stock model (locale, banned/banReason/banExpires, impersonation, API-key rate limiting).
